# Harness Run

围绕用户目标持续推进可运行切片，以真实证据验收；文档保持简洁，重要决定跨会话留存。宿主管理运行、权限和预算。

## 新建项目与现有项目

先读适用仓库指令和用户目标，根据实际代码与运行入口选择路径：

- **新建项目**：明确用途、关键用户路径和约束，按 [project-setup.md](references/project-setup.md) 建立基础与最小可运行骨架，随后实现首个可验收切片。用户明确仅需初始化时完成初始化范围。
- **现有项目**：先核对代码、运行与测试基线及已有记录。首次接入按 [existing-project.md](references/existing-project.md) 将有效内容合并到标准架构、计划和 `docs/design/` 专题，更新引用并核验后清理旧文件、跳转入口及迁移副本，统一使用新体系。已接入项目增量维护并收拢遗留文档；中断后从当前计划接续。已有任务读接续摘要，新需求在现有架构上规划切片。

首次接入以 AGENTS.md 作为共享指令入口，按 [project-setup.md](references/project-setup.md) 补齐短导航与记录约定，并按 [memory.md](references/memory.md#首次注册项目-hook) 注册项目 hook。显式调用 skill 时核对一次当前宿主的注册与会话目录；配置一致则复用，版本或路径变化导致差异时更新。仅触发 skill、尚未给出开发目标时，默认完成项目接入。

两种路径进入相同的实施、验证、修正和记忆留存循环。只在首次接手、上下文丢失或相关信息变化时重新定位。

新会话或压缩后，先核对计划的接续摘要：当前目标、最新用户约束、当前切片、已验证版本、待验收项和下一动作。结合当前代码、工作区变更及证据确认事实。历史有疑问时先查少量摘录，再展开原文；查询顺序和工具见 [memory.md](references/memory.md)。召回内容按来源、条件和决定状态使用，异常替代关系先核对。

## 推进与完成

1. 从用户路径推导模块依赖、可验收里程碑和验证入口；说明重要假设后执行。只有无法推断且实质影响方向的选择才询问用户。
2. 跑通当前切片的构建、启动和相关验证入口；从基线中识别阻碍目标的问题。
3. 按用户价值、依赖、风险及验收缺口选择下一项。实施、检查、修正后继续目标内剩余工作；失败重复且缺少新证据时更换诊断方法。保留用户和其他执行者的改动。
4. 设计验证或准备验收时读 [verification.md](references/verification.md)。预期结果来自需求、契约或独立依据；交互目标通过真实程序操作核对结果，证据关联被测版本。
5. 对照原始目标完成最终回归和必要真实验收，刷新受最后改动影响的证据。计划、实现或局部测试完成后继续处理剩余验收项；工具缺失时记录具体缺口并推进可行工作。

已有原生 goal 直接沿用；启动、接续、暂停或处理预算时读 [native-runtime.md](references/native-runtime.md)，遵守当前宿主能力与用户授权。目标完成后交付结果和证据；停止、限额或外部阻塞时保存真实进度及下一步。

## 留存与按需读取

在用户修正、重要决定、里程碑、阻塞、交接或交付时，按 [conventions.md](references/conventions.md) 更新记录：一份计划承载 TODO、进度与接续，架构总览链接 `docs/design/` 中的现行专题，一份 history 汇总结果并链接依据。用户指定单独记录的内容保留独立文档。已否决方案保留条件和原因；决定变更注明替代关系。写完回读，核对含义及链接。

普通实现循环沿用已有上下文。稳定指南和空白模板按需维护；详细日志、截图及报告保留在正常产物位置，记录引用关键证据。每项工作关联用户目标或已证实的阻塞，完成判据保持稳定。
