# 项目检查与按需初始化

每次接手先检查实际项目；仅在需要补齐基础结构时读取本文件和 [init-files.md](init-files.md) 中相应模板。检查不生成独立报告，不每轮重做。

## 判断是否就绪

查看适用的 AGENTS/CLAUDE 指令、根目录与相关 docs 索引，再按需读取：

- 项目用途、当前启动/测试入口是否可确定。
- 是否有真实架构或足够说明模块、接口、依赖和数据流的等价内容。
- 长期任务是否有可接续的目标、进度、验收条件和下一步。
- 是否已有计划、历史及协作约定；模板所指向的文件是否存在且有用。

文件存在不代表内容可用；空壳、占位符、失效命令要结合源码修正。反过来，缺少模板中的某个文件名也不代表未初始化：现有 README、architecture、roadmap、任务计划和 changelog 可承担等价职责。

| 项目现状 | 处理 |
|---|---|
| 空项目，或用户明确要求完整初始化 | 按下面的基础骨架实例化，再推进首个可运行切片 |
| 已有 harness-run 基础结构 | 保留已有内容，仅补缺失且需要的文件、修复失效导航 |
| 已有其他成熟文档结构 | 映射并沿用等价文件；补真实信息缺口，不另铺一套 guides、plans 或 histories |
| 基础已就绪 | 直接进入规划、实现与验证 |

调整文档维护节奏时，保留项目特有的质量门禁和协作约束，只在已授权范围内修改通用规则，不把模板当成覆盖既有指令的依据。

## 基础骨架

新建项目使用以下基础文档和模板：

```text
<project>/
├── AGENTS.md
├── CLAUDE.md
├── README.md
├── CODEOWNERS                 # 已知真实负责人时配置
├── LICENSE                    # 已确定项目许可时生成
├── .editorconfig
├── .gitattributes
├── .gitignore
├── .markdownlint.json
└── docs/
    ├── ARCHITECTURE.md
    ├── REPO_COLLAB_GUIDE.md
    ├── PLANS_GUIDE.md
    ├── HISTORY_GUIDE.md
    ├── exec-plans/
    │   ├── README.md
    │   ├── tech-debt-tracker.md
    │   ├── active/.gitkeep
    │   ├── completed/.gitkeep
    │   └── templates/execution-plan.md
    └── histories/template.md
```

这是初次建立的基础，不是每次调用都要重新生成的文件集。已有约定时可省去等价文件。专用 SECURITY、RELIABILITY、CICD、FRONTEND、DESIGN 等模板按需使用；不要仅因项目属于某种类型就创建专题文档。

## 实例化与补齐

1. 从目录、源码、用户目标和已有元数据推断项目名、类型与约束。技术选型在授权范围内自行决定；只询问无法推断且实质影响方向的信息，不把名称、作者、团队等模板字段变成开发前置问卷。
2. 按缺口读取模板的对应章节。已有文件定点编辑，保留自定义内容；基础配置只合并适用规则，不覆盖技术栈默认值、忽略规则、版权或所有权。
3. 实例化 README 的用途与运行入口、AGENTS 的导航、ARCHITECTURE 的模块和数据流。新项目尚无实现时标明拟定结构；首个切片落地后更新为事实。无需为了模板创建 apps/packages/infra。
4. 保留计划与历史模板供后续复用。未开始的实现不记为完成历史，模板占位可留在模板文件中，不能留在当前项目说明中。许可证和 CODEOWNERS 不明时保留已有内容或暂不生成，不填虚构身份；不阻塞其余工作。
5. 新文件默认中文、UTF-8、LF；已有仓库沿用其语言、缩进和格式。模板没有附带脚本，不限制实现真实项目所需的构建、测试和验收脚本。
6. 核对导航可达、关键文档有实际信息，配置与当前项目相容。运行入口在代码具备后实际执行；未执行不能写成已验证。

基础就绪后直接进入目标的实施循环，不把“创建完文档”当成软件目标完成，也不以“请用户继续开发”结束。用户明确只要初始化时，完成该范围即可。

## 低维护约定

- AGENTS 保持短导航；规则指南和空白模板通常只在协作制度变化时维护。
- 一个持续目标沿用一份执行计划；进度、下一步和交接在该计划中维护。
- 架构只在模块边界、接口、依赖或数据流变化时更新。
- 一个实质变更任务沿用一份 history，在交付时汇总；长任务需要阶段留档时更新同一份。普通修复循环不追加历史。
- 不生成独立的初始化状态文件、逐轮日志、handoff、completion 或新的 `.harness-run/` 文档体系。

详细记录与接续约定见 [conventions.md](conventions.md)；项目已有有效指南时优先使用项目指南。
