# 原生持续执行

在启动或管理长程执行、委派子代理或判断仓库操作边界时读取。宿主决定运行生命周期；执行协议不模拟这些能力。

## 能力选择

| 当前情况 | 行为 |
|---|---|
| 已有与用户目标一致的原生 goal | 沿用当前目标和预算，持续执行并留下工程记录 |
| 用户要求创建或启动目标，且宿主提供相应工具 | 按工具约定建立目标；不要额外要求用户重复确认已授权的动作 |
| 宿主只提供交互式 `/goal` 入口 | 在需要时给出准确入口；能在当前会话推进的工作继续做，不假装已经启用自动续跑 |
| 当前环境没有原生持续执行能力 | 在当前会话完成可做的工作并留下交接，明确自动续跑尚未启用 |
| 用户只是在讨论方案、评价 skill 或询问状态 | 回答问题或读取状态，不启动目标或后台进程 |

先用当前可用工具及宿主文档判断能力，不因为某产品的其他版本支持功能就假设当前入口支持。slash 命令是宿主交互，不作为终端 shell 命令执行。

## 宿主适配

- **Codex**：优先使用当前会话暴露的 goal 工具或原生 `/goal`。只有用户明确要求设置目标时才创建；已有目标可用时不重复创建。预算仅按用户明确要求设置。暂停、恢复、阻塞和完成遵循当前工具的约束。
- **Claude Code**：使用当前版本提供的 `/goal` 管理有完成条件的持续任务。周期性检查才考虑 `/loop` 或 `/schedule`，且只在用户要求周期执行时使用；一次持续开发不需要额外定时器。
- **Antigravity**：持续目标、上下文压缩和定时任务分别由用户在输入框触发 `/goal`、`/compact`、`/schedule`，agent 在需要时提示准确入口，不在终端执行 slash 命令；已授权的子代理（如界面真实验收使用的 `browser`）、后台任务或 `schedule` 工具按宿主规则配合使用。工作区根目录 `AGENTS.md` 由宿主常驻加载，新会话同时通过 `.agents/hooks.json` 注入导航。
- **其他宿主**：选择实际存在且授权的等价能力。没有等价能力就说明边界，不编造命令，也不自动安装守护进程。

skill 的完成标准仍需落实到项目证据。宿主的完成评估不能替代实际运行测试或操作程序。

## 子代理委派与仓库边界

宿主支持子代理或外部编码工具且独立拆分确有收益时，按任务复杂度匹配模型开销，并遵守三项契约：

- **边界隔离**：并行修改按模块或文件划清职责，优先使用 Git Worktree 或宿主原生的隔离工作区（如 `share` / `branch`），避免多执行者同时写入同一目录。
- **最小上下文投喂**：只向子代理提供当前子任务目标、关联文件、实现约束和可执行的验收条件，不转发整仓无关背景，避免重复做相同调研。
- **独立审查**：子代理返回后，主 Agent 对照原始问题、架构边界、潜在回归及多余依赖/重复代码独立核验改动与证据，不直接转发未经核实的自评结论。

未经用户明确授权，不自动合并主干分支、推送远端、关闭或合并外部 Issue/PR、删除重要数据或执行生产环境部署。

## 控制与接续

- 用户要求状态时，报告实际目标状态、已验证结果、当前切片和主要缺口，继续原任务，除非用户要求停止。
- 用户修改目标或约束时同步计划，重评受影响的验收；不要把中途问题误当取消原任务。
- 用户暂停或停止时，先服从宿主停止机制，在允许的范围内保存已知状态，不再开始新的实质工作。
- 到达预算或宿主限额时留下下一步，不能自行扩大预算、绕过限制或另起会话继续消耗。
- 新会话、压缩上下文或跨宿主接手时先读当前计划的接续摘要，核对最近用户修正、被测版本和待验收项，再检查实际文件。原生目标的接续按当前宿主能力核实。

上下文事件入口和去重账本见 [memory.md](memory.md)。缓存只记录入口投递元数据，工程事实保存在项目原有文档中；compact/clear/resume/fork 重新提供导航。使用通用事件命令或按宿主实际 hook 契约接入，持续运行仍由原生 goal 管理。
