# 记录、决定与接续

建立记录、保存重要结论或交接时读取。接入后按下表维护现行文档，同一信息维护一处，其他位置链接。用户指定路径和保留的机器依赖入口在导航中注明。文档维护聚焦内容准确和可接续，沿用现有排版。模板见 [init-files.md](init-files.md)。

## 内容归属

| 内容 | 默认位置 | 更新时机 |
|---|---|---|
| 简短导航 | AGENTS.md | 入口变化 |
| 目标、TODO、里程碑、进度、接续摘要 | docs/exec-plans/active/ 当前计划 | 用户修正、里程碑、阻塞、交接 |
| 模块、依赖、数据流 | docs/ARCHITECTURE.md | 结构事实变化，链接详细设计 |
| 专题方案、业务规则、接口契约、用户指定独立记录 | docs/design/<name>.md；用户指定路径优先 | 相应要求或规则变化 |
| 研究结论、失败方案及条件 | 对应 design 专题或当前计划的重要决策 | 有后续复用价值时 |
| 已交付变更摘要 | docs/histories/ 同一任务 history | 交付或必要阶段留档 |
| 当前目标外的已证实问题 | docs/exec-plans/tech-debt-tracker.md | 发现问题、处理状态变化 |
| 接入前原始资料及迁移索引 | docs/archive/legacy-<date>/ | 首次迁移，恢复时核对原索引 |

复杂或长期目标沿用一份计划。按用户路径定义可验收里程碑，记录模块依赖与风险，优先解除阻塞和打通主要路径。目标内剩余工作留在该计划；目标外已证实的实现或维护缺陷进入技术债清单。既有未完成需求与待验收事项留在活动计划，待排期时注明状态和下一动作；文档接入完成后仍保留开发任务入口。原目标达成后归档到 completed/，同时修复导航。

## 记住重要结论

用户要求记住、修正约束，或实现中确认可复用规则时：

1. 定位现有主题；已在上下文中的内容直接使用，需要找位置时按 [memory.md](memory.md) 检索。
2. 将现行结论写入对应架构、接口或使用说明；尚在探索的取舍留在计划或既有研究文档。注明适用条件和来源，区分用户确认、验证事实与推断。
3. 决定反转时更新现行正文，给旧决定留下状态、替代位置和必要原因。被否决方案记录失败条件，后续重试需要新的相关证据。
4. 回读改动，核对措辞、数量、条件及用户修正；随后在计划或 history 链接实际保存的位置。分别核实正文与链接的写入结果。

长期规则在计划归档前完成上述整理；普通尝试沿用会话上下文。有独立维护价值的专题放入 `docs/design/`。用户明确要求单独记录时建立或保留该文档，短文档也有独立入口；指定名称与路径优先，架构或计划链接它。

多执行者共用文档时采用定点更新；写入发现旧内容已变化，重新读取后合并并回读双方条目。共享摘要或决定出现实质冲突时，由当前协调者统一确认现行内容。

局部文档约定调整时，定点更新现行条目及接续摘要，核对改动段落、引用和直接影响即可。沿用未受影响的验证结果，普通核对结论留在回复；需要复现技术行为或用户要求独立交付时，再保存专门报告。history 在交付或必要阶段归并更新。

## 决定状态与替代

重要决定使用 `accepted`（已确认）、`proposed`（推断/待确认）、`rejected`（已否决）、`superseded`（已替代）。普通正文可继续使用自然语言。需要脚本解析时，将元数据放在文档 frontmatter 或标题后的首段：

```markdown
## export-id-v2
status: accepted

结论：导出保留对象 ID。
条件：文件格式 v2。
依据：用户确认；往返验证见 tests/export-id 的报告。

## export-id-v1
status: superseded
superseded_by: #export-id-v2

旧方案：导出时重新编号；已发现外部引用失效。
```

章节用稳定标题作为 ID，或使用 `## 标题 {#decision-id}`。跨文件目标写仓库相对路径，可带 `#章节ID`。文件级替代适用于整篇主题，单项反转使用章节级关系。已否决、已替代和待核对状态覆盖该标题下的子节；现行替代决定放在同级或独立主题。目标缺失、越界、自指、重复 ID、成环、指向原始归档或超过八跳时按 `needs-review` 待核对；修复关系或查明现行依据后执行相关决定。更新时间仅供参考。

`docs/archive/` 保存原始证据，原文状态保留；现行规则从架构、design 和当前计划读取。原文到现行内容的关系保存在迁移索引，归档过程按 [existing-project.md](existing-project.md) 执行。

## 接续与证据

在同一计划顶部维护短摘要：当前目标、最新用户约束及来源、当前切片、已验证版本/变更范围与证据、待验证项、下一动作、重要阻塞。用户修正先同步该摘要和受影响规则，再继续实施。重要失败尝试可用一行链接原因。

新会话、压缩或跨宿主接手先恢复摘要，核对最近用户修正与原始来源，再检查相关代码和工作区变化。原始会话按宿主可用历史工具查找；恢复近期约束时优先保留压缩前最后几轮。存在冲突时标明具体争议和来源，保留可行工作继续推进。

证据记录执行命令/场景、实际结果、代码版本或工作区变更范围和产物位置。仅刷新过期、受影响或不足的检查。history 汇总用户诉求、关键改动、设计依据和验收结果，同一任务跨轮次继续使用同一文件。纯问答、普通测试运行及工具流水记录留在会话中。
