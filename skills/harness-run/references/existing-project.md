# 现有项目文档整合

首次接入已有项目，或清理此前遗留的文档体系时读取。目标是把有效内容完整承接到标准文档，同一信息维护一处。完成后统一使用新体系，清理旧文件、跳转入口和迁移副本；不新建 archive、originals 或独立迁移账本。

## 整合与切换

1. **清点内容和依赖。** 读取适用指令、已有文档、最新用户要求、代码与测试入口，并核对 Git 状态及未提交改动。定位旧路径在文档、源码、配置、测试、发布流程和 hook 计划绑定中的引用；检查模板字符串、分段路径拼接及目录树说明。
2. **按职责合并。** 按下表整理内容，复用有效正文，合并重复说明。架构对照实现，约束对照最新用户要求，进度对照验证证据。保留未完成需求、重要失败条件和决定变化；信息冲突或证据不足的内容在相应主题中标为待核对。已有标准文档直接补充。
3. **更新消费者。** 将 AGENTS、README、索引、相对链接、图片附件、程序读取、打包配置和 hook 计划绑定切换到新位置。同步修正 `superseded_by` 的文件路径和章节引用，保留 URL 目录末尾斜杠等路径语义。实际运行受影响的生成器和读取入口，核验输出位置及发布包内引用；移动计划后执行已注册 hook，检查导航和 stderr。
4. **核验并清理。** 回读新文档，逐项确认用户约束、旧 TODO、关键决定与必要证据已承接，运行受影响的构建或契约检查。随后删除旧位置文件、跳转入口及重复副本，检查失效引用和内容重叠。整合完成与下一动作归入同一任务的计划或 history。

旧文件保留到对应内容和消费者核验完成，再执行清理。大目录可分批处理，接续点写在新体系的当前计划；中断后核对当前文件与工作区变化，继续未完成批次。Git 已有历史可按提交和原路径追溯，未提交内容需核对完整承接。

其他开发会话仍在推进同一项目时，协调正在写入的文档及其消费者切换。写入前重新读取，合并同期新增的约束、进度和验收证据；尚在协调的文件记为待切换，清理完成后再登记该批完成。

## 内容归属

| 内容 | 位置 | 整理依据 |
|---|---|---|
| 模块、依赖、接口入口、数据流 | `docs/ARCHITECTURE.md` | 按实际代码和配置简述，链接详细设计 |
| 专题方案、业务规则、接口契约、独立说明 | `docs/design/<name>.md` | 合并同主题有效内容，保留适用条件、决定及依据 |
| 目标、TODO、里程碑、进度、接续摘要 | `docs/exec-plans/active/<task>.md` | 同一目标维护一份计划，待排期需求注明状态与下一动作 |
| 已完成计划、已交付变更 | `docs/exec-plans/completed/`、`docs/histories/` | 保留有价值的结果、原因、日期、版本与证据 |
| 当前目标外的已证实问题 | `docs/exec-plans/tech-debt-tracker.md` | 具体问题及后续动作 |
| 图片、契约附件、测试证据 | 对应专题附件位置或项目正常产物位置 | 保留仍被使用的必要材料，并从正文链接 |

一个旧文件可拆入多个去向，多个旧文件也可合成一个专题。用户要求单独记录时在 `design/` 建立独立文件，篇幅可短；明确指定名称或路径时遵循用户要求。旧草案中的有效结论和有复用价值的失败原因并入对应专题，未来方案标为拟定，待核对事项留在相关主题或计划。

已实现但尚无充分验收证据的事项记为“已实现，待验证”；有可追溯测试或真实验收结果的记为“已验证”。本轮仅做接入时，将既有开发需求整合到活动计划并注明下一动作；接入完成后继续使用这份计划。

此前已有旧文档目录或迁移归档时，也按上述流程收拢：核对其中独有的约束、决定、TODO 与必要附件，整理到标准位置并更新引用，再清理旧资料及空目录。重复触发增量维护现行文件。模板见 [project-setup.md](project-setup.md)，决定与接续约定见 [conventions.md](conventions.md)。
