# 现有项目接入与资料整理

首次接入已有代码或文档的项目时读取。目标是形成简洁的现行文档层，完整保留来源，接续正在进行的工作。已有标准结构直接增量维护；发现未完成的迁移索引时从检查点继续。

## 先保存，再整理和切换

1. **清点来源与依赖。** 读取适用指令、文档目录、已有计划及当前代码入口。查找文档内的相对链接、图片和附件，以及 README、源码、配置、测试、文档站点对旧路径的引用。根目录 README、AGENTS 和程序依赖的文档入口继续可用。用户指定名称或位置的文档按其要求保留。
2. **保存原始快照。** 在 `docs/archive/legacy-YYYY-MM-DD/` 建一份迁移索引，将本次整理的原文和依赖附件按仓库相对路径复制到 `originals/` 下，例如 `originals/docs/old-design.md`。包含散落在其他目录中且将被改写的资料，保留二进制附件、有效说明及已存在的标准文档原文。先核对清单、文件数量和内容哈希，再将索引阶段改为“快照已核验”。后续整理从当前源文件或快照取材，快照原文保持原样。
3. **结合证据整理。** 按下面的内容归属建立现行文档，复用旧资料的有效正文。架构对照源码、配置和运行入口；目标与约束对照最新用户要求；进度对照测试和验收证据。每份资料在索引中记录现行去向、处置及待核对内容，重要结论保留具体来源链接。
4. **核验后切换。** 新文档内容和入口就绪后更新 AGENTS、README、计划索引及入站引用，修正移动后的相对链接、图片、附件和 `superseded_by` 仓库路径。运行受影响的构建、文档站点或契约检查。随后清理已整理且快照完好的旧工作副本；存在外部链接、发布地址或机器依赖的路径，保留转向入口或作为权威源继续维护，并在标准文档中链接它。最后把迁移索引标为“完成”，保存当前任务的下一动作。

复制和切换分阶段执行，使中途停下时项目仍有可读入口。大目录可分批推进，各批核验完成后再切换对应文件。归档目录本身、构建缓存和无关产物排除在快照来源之外；已有归档直接引用。指向仓库外的链接记录原目标和待处理事项，按实际授权范围处理。

其他开发会话仍在推进同一项目时，保留其正在维护的计划和固定契约路径，通过标准索引接入，避免并行维护两份状态。写入前核对原文是否变化；同期新增的约束、进度和验收证据按最新内容保留。核验分别记录本轮改动与同期变化，测试结果绑定实际执行时的版本。

## 现行内容放在哪里

| 内容 | 默认去向 | 整理依据 |
|---|---|---|
| 模块、依赖、接口入口、数据流 | `docs/ARCHITECTURE.md` | 实际代码和配置，简述结构并链接详细设计 |
| 设计方案、业务规则、接口契约、用户要求单独记录的内容 | `docs/design/<name>.md` | 复用核对后的旧专题，保留适用条件、重要决定和依据 |
| 当前目标、既有未完成需求、TODO、阶段进度、接续摘要 | `docs/exec-plans/active/<task>.md` | 最新用户目标及真实证据，同一目标维护一份计划，待排期的原目标注明状态 |
| 已完成计划、已交付变更 | `docs/exec-plans/completed/`、`docs/histories/` | 有证据的完成结论，保留旧时间和来源 |
| 当前目标外的已证实问题 | `docs/exec-plans/tech-debt-tracker.md` | 具体问题及后续动作 |
| 原始资料、旧草案、暂时无法确认的历史说法 | `docs/archive/legacy-<date>/originals/` | 原样保存，在索引记录去向或待核对点 |

已实现但尚无充分验收证据的事项记为“已实现，待验证”；有可追溯测试或真实验收结果的记为“已验证”；信息冲突或证据不足的记为“待核对”。旧 TODO 逐项核对，保留尚未完成的用户要求和关键失败原因。

本轮仅做接入时，接入完成后将既有开发需求留在活动计划，注明待排期及下一动作；继续使用原开发计划，缺少时按原目标归并一份。技术债清单用于已证实的实现或维护缺陷；待开发能力和待验收事项留在计划，拟定选型留在设计。历史口头完成声明记录为待核对，并保留核对入口。

一个旧文件可拆入多个去向，多个旧文件也可合成一个现行专题。设计方案涉及未来工作时明确标注拟定内容。用户指定单独记录即建立或保留独立文件，篇幅可短，并从相关架构或计划链接。

归档表示资料的保存位置，决定状态另按证据维护。已反转的决定在现行文档中记清适用范围与替代关系；原始快照通过迁移索引连接现行位置。归档默认退出普通 recall，需要核对来源时用 `--source docs/archive/legacy-<date>` 显式检索，详见 [memory.md](memory.md)。

## 一份索引恢复迁移

以 `docs/archive/legacy-<date>/README.md` 作为唯一迁移索引，来源清单、哈希、去向与状态统一维护在下表中。核验脚本直接读取它，临时中间数据放在临时产物目录。记录示例：

```markdown
# 原始资料与迁移索引

- 阶段：保存中 / 快照已核验 / 整理中 / 完成
- 来源范围与时间：
- 当前批次、待核对项和下一动作：

| 原路径 | 快照路径 / SHA-256 | 现行去向 | 处置与验证 |
|---|---|---|---|
| docs/old-design.md | originals/docs/old-design.md / <hash> | docs/design/export.md | 已核对代码；入站引用已更新 |
```

首次写索引时列出完整来源清单，包括附件；逐批更新快照哈希和整理状态。开始下一批或恢复前回读索引并核对实际文件。已保存且哈希一致的快照复用；缺失的条目继续保存。来源发生变化时保留已保存原文，将变化另存并登记，再决定现行内容；存在未核验快照或并发改动时先保全双方内容，再完成对应切换。

重复触发沿用本次索引与现行文档；跨日恢复沿用原批次日期。以后新增资料通常直接整理到对应位置。一次全新且明确需要保存的迁移可另建批次，同日使用后缀避免覆盖。模板和接入步骤见 [project-setup.md](project-setup.md)，决定与接续约定见 [conventions.md](conventions.md)。
